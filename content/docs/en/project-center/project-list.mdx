Use search when you know a project's name, or sort by creation or modification time to browse the list. Descriptive, consistent names make it easier to find the right site, customer or review version as the workspace grows.

## Steps

1. Use the **search** field to find a project by keyword.

2. Or use the **sort** control to order the list by creation time or last modified time.

3. Open the project to load it in the editor.

## Choosing a sort order

| Sort by | Puts at the top | Use when |
| --- | --- | --- |
| Last modified | Recently edited and saved projects | Resuming active work, or finding what a colleague touched most recently |
| Creation time | Projects in the order they were created | Tracing a batch of projects, or reviewing earlier deliveries in sequence |

- **Daily work**: last modified, since active projects surface without being searched for
- **Auditing a delivery, or finding something historical**: creation time

## What makes a project findable

Search matches only what a project is called. Findability is decided earlier, in [Project Settings](/worldbuilder/en/docs/step-by-step-workflow/2-project-settings).

| Practice | Effect on the list |
| --- | --- |
| Descriptive titles naming the site, asset, or customer | Search returns the right project on the first attempt |
| A representative cover image | The project is recognisable before it is opened |
| Consistent naming across a batch | Related projects group together when sorted |
| Project type set accurately | The list reflects what kind of scene each project holds |

Choose names and covers that a colleague unfamiliar with the project can recognize.

## Why it matters

Search and sorting keep discovery efficient as the portfolio grows, which matters most when teams move between several projects in the same week.

Finding existing work also makes it easier to reuse a project instead of creating it again.
