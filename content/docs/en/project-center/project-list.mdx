The project list is the browsing view for every digital twin project in the workspace. Search finds a project directly; sorting orders the portfolio when you are not sure what you are looking for.

Both matter more than they appear to at the start. A workspace with five projects does not need either. A workspace with fifty depends on them.

## Steps

1. Use the **search** field to find a project by keyword.

2. Or use the **sort** control to order the list by creation time or last modified time.

3. Open the project to load it in the editor.

## Choosing a sort order

| Sort by | Puts at the top | Use when |
| --- | --- | --- |
| Last modified | Recently edited and saved projects | Resuming active work, or finding what a colleague touched most recently |
| Creation time | Projects in the order they were created | Tracing a batch of projects, or reviewing earlier deliveries in sequence |

Sorting by last modified is the better default for day-to-day work, because active projects surface without being searched for. Sorting by creation time is more useful when auditing a delivery, tracing a batch, or looking for something historical whose name nobody remembers.

## What makes a project findable

Search only works against what a project is called, so findability is decided earlier, at [Project Settings](/en/docs/editor/editor-panels/scene-panel/project-settings), not here.

| Practice | Effect on the list |
| --- | --- |
| Descriptive titles naming the site, asset, or customer | Search returns the right project on the first attempt |
| A representative cover image | The project is recognisable before it is opened |
| Consistent naming across a batch | Related projects group together when sorted |
| Project type set accurately | The list reflects what kind of scene each project holds |

The cost of skipping this is not felt during creation. It is felt three months later, by someone who was not on the project, trying to find it.

## Why it matters

Search and sorting keep project discovery efficient as the portfolio grows. That matters most when teams switch between project setup, editor refinement, stakeholder review, and follow-up maintenance across several projects in the same week.

The failure this prevents is a specific and expensive one: rebuilding something that already exists because nobody could locate it. A portfolio that stays navigable is what makes duplication and reuse practical rather than theoretical.
