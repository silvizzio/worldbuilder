Project actions control the project itself: updating it, copying it, sharing it, and removing it.
The editor controls what is inside it.

They are often confused with the save, preview, and publish actions inside the editor.
Those are covered in [Publish Project](/en/docs/editor/project-actions).

The line between them is functional:

- **The editor** controls project content
- **The Project Center** controls the project itself

## Action reference

| Action | What it does | Use it when |
| --- | --- | --- |
| Edit project | Updates project name, cover image, and basic information, or opens the project in the editor | Metadata is out of date, or you are returning to continue scene authoring |
| Duplicate project | Creates a copy of the project, reusing its scene structure and configuration | Building a similar scenario, preparing an alternate version, or preserving a baseline before major edits |
| Share project | Generates a share link or publishing entry, with access control | A reviewer or customer needs to see the project without opening the editor |
| Delete project | Removes the project from the portfolio | The project is finished with and is cluttering the list |

## Edit project

Use **Edit project** to update the project name, cover image, or basic information, or to reopen the project in the editor.

Accurate metadata is what makes a project findable, and neglecting it falls to whoever needs the project next.
Update it before sharing with reviewers, so the name and cover a stakeholder sees match what they are being shown.

## Duplicate project

Use **Duplicate project** to copy an existing project along with its scene structure and configuration.

A finished project is a working baseline: scene settings tuned, assets placed, markers written, UI built. Duplicating starts from there rather than an empty scene.

| Use duplication for | Instead of |
| --- | --- |
| A new customer variant of the same scene | Rebuilding the scene and re-adding markers |
| An updated capture of the same site | Starting a fresh project and reconfiguring everything |
| A significant restructure you might reverse | Editing in place and hoping undo is enough |
| Alternate versions for a review | Presenting one version and describing the other |

It is also the safe way to explore a large change. Duplicate first, edit the copy, and the original stays intact for comparison or rollback.

## Share project

Use **Share project** to generate a share link.

| Access setting | Suits | Consider |
| --- | --- | --- |
| Disabled | Work in progress, internal only | The link exists but resolves to nothing for recipients |
| Public | Open demonstrations, marketing, wide distribution | Anyone with the link can open the project |
| Password protected | Customer reviews, commercially sensitive scenes | The password must reach the recipient through a separate channel |

Save and preview before sharing externally.
A share link serves the saved state, so whatever was last saved is what the reviewer opens, regardless of what your editor currently shows.

## Delete project

Use **Delete project** to remove a project that is no longer needed.

Before deleting, consider whether it might still be wanted for:

- Historical reference
- Customer demonstration
- Version comparison

Duplication has minimal cost, and a superseded project is often the only record of a given state at a point in time.
