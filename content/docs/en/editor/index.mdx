Use the **online editor** to turn 3D assets into an interactive scene.
Positioning models, labelling them, building the interface, and publishing all happen in one browser tab.

The editor keeps model placement, annotations, and interface controls in the same project, so you can review them together.

After making a change, save and preview the project before sharing its link.

## Why the editor is panel-based

The four panels separate the main authoring tasks so team members can find the controls relevant to their work.

Separating them keeps each concern independent:

- A **3D content operator** places assets without touching interaction logic
- A **solution engineer** builds the UI layer without needing to understand asset alignment
- Both contribute to the same project through the panels relevant to their roles

| Panel | Owns | Typically operated by | Documentation |
| --- | --- | --- | --- |
| Scene Panel | Project identity, camera behaviour, lighting, post-processing | Project owner, 3D operator | [Scene Panel](/worldbuilder/en/docs/step-by-step-workflow/2-project-settings) |
| Model Panel | Bringing 3D models in, positioning them, checking they sit right | 3D content operator | [Model Panel](/worldbuilder/en/docs/step-by-step-workflow/3-upload-models) |
| Marker Panel | Labels pinned to the scene, and what happens when you click them | Solution engineer | [Marker Panel](/worldbuilder/en/docs/step-by-step-workflow/7-add-markers) |
| UI Panel | The flat interface on top: pages, buttons, text, and what they do | Solution engineer | [UI Panel](/worldbuilder/en/docs/editor/editor-panels/ui-panel/canvas-settings) |

Alongside the panels, project actions handle save, preview, publish, and undo. See [Publish Project](/worldbuilder/en/docs/step-by-step-workflow/9-save-and-preview).

## Working order

The panels have separate controls, but this order helps avoid rework:

1. Configure the scene
2. Load and place assets
3. Attach markers
4. Build the UI above them

Each layer references positions the previous one established:

- Move a model after markers are attached, and every marker on it needs revisiting
- Create target pages and models before connecting UI interactions to them

[Step-by-step Workflow](/worldbuilder/en/docs/step-by-step-workflow) sets out the full ten-step path and where teams commonly lose time.

## What the editor replaces

| Conventional approach | In the editor |
| --- | --- |
| A 3D application for positioning models | Model Panel, with drag handles and typed values |
| A document or spreadsheet holding annotations | Markers attached to the positions they describe |
| A developer building a front end around the asset | UI Panel, with pages, components, and interactions |
| A deployment step to make changes visible | Save, preview, share, inside the same workspace |

Keeping these tasks together makes it easier to update and review a scene.

## Why it matters commercially

- **During a review**: feedback can be applied in the editor, previewed, and shared for another review
- **Across a team**: scene configuration, annotation, and interface design become tasks for a solution engineer rather than a 3D specialist

Teams can prepare customer variants and presentations using the existing reconstructed assets.
