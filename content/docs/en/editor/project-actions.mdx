These are the delivery actions inside the editor: save current changes, preview the saved version, generate a sharing entry, or discard unsaved draft changes.

The sequence matters. Save writes the state, preview shows what was written, publishing exposes it. A share link always serves the saved state, so previewing before sharing is the only way to confirm a reviewer sees what you intended.

## Action reference

| Action | Description | Recommended usage |
| --- | --- | --- |
| Save | Writes the latest project edits and synchronises them to cloud storage. | Save after meaningful scene, model, marker, or UI changes, before previewing. |
| Preview | Opens the saved project output for review. | Use as the checkpoint before publishing or sharing. |
| Publish and Share | Creates a shareable project entry and controls access state. | Confirm the project is ready for review or demonstration before enabling access. |
| Undo Changes | Discards unsaved local draft changes and returns to the last saved version. | Use during iteration when the current draft should not be committed. |

## Save and preview

Use **Save** to write modified content and synchronise it to cloud storage. After saving, the preview page displays the latest content, so you can confirm scene presentation, asset placement, UI layout, and interaction behaviour before publishing.

This matters most when several elements have changed at once. Individual changes are easy to judge in the editor; how they work together is only visible in preview, and interaction behaviour in particular cannot be fully evaluated from the authoring view.

## Publish and share

Use **Publish and share** to generate a share link. Access can be disabled, opened publicly, or protected with a password, depending on whether the audience is a customer demo, a team review, or external viewing.

Publishing converts the edited project into an accessible review entry point, so stakeholders can see results without entering the editor. That is the step that makes a digital twin a deliverable rather than a working file.

## Undo changes

Use **Undo changes** to discard unsaved local draft changes and return to the last saved version. This limits the impact of accidental edits and gives a controlled way to recover before changes are committed.

Most useful during iterative layout, model positioning, UI tuning, or interaction configuration, when comparing the current draft against the last stable state is the fastest way to decide whether to keep going or start again.

For changes you may want to reverse after saving, duplicate the project first. See [Project Actions](/en/docs/project-center/project-actions).
