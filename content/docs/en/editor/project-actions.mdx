These are the delivery actions available inside the editor: save, preview, publish, and undo.

Run them in that order. Saving writes your changes, preview opens the saved version,
and publishing makes it accessible to others.

The order matters because a share link always serves the saved version rather than
what your editor currently displays. Previewing before you share is the only way to
confirm that a reviewer will see what you intend.


## Action reference

| Action | Description | Recommended usage |
| --- | --- | --- |
| Save | Writes the latest project edits and synchronises them to cloud storage. | Save after meaningful scene, model, marker, or UI changes, before previewing. |
| Preview | Opens the saved project output for review. | Use as the checkpoint before publishing or sharing. |
| Publish and Share | Creates a shareable project entry and controls access state. | Confirm the project is ready for review or demonstration before enabling access. |
| Undo Changes | Discards unsaved local draft changes and returns to the last saved version. | Use during iteration when the current draft should not be committed. |

## Save and preview

**Save** writes modified content and synchronises it to cloud storage. After saving, the preview page displays the latest content, so you can confirm:

- Scene presentation
- Asset placement
- UI layout
- Interaction behaviour

This matters most when several elements have changed at once.
You can judge individual changes in the editor.
How they work together is visible only in preview, and interaction behaviour in particular cannot be fully evaluated from the authoring view.

## Publish and share

Generates a share link.
Access can be disabled, opened publicly, or protected with a password.
The choice depends on the audience: a customer demo, a team review, or external viewing.

Publishing converts the edited project into an accessible review entry point, so stakeholders can see results without entering the editor.
That step turns a digital twin into a deliverable.

## Undo changes

Discards unsaved local draft changes and returns to the last saved version.
This limits the impact of accidental edits and gives a controlled way to recover before changes are committed.

Most useful during iterative work.
Comparing the current draft against the last stable state is the fastest way to decide whether to continue or start again.

For changes you may want to reverse *after* saving, duplicate the project first. See [Project Actions](/en/docs/project-center/project-actions).
