A **marker** is a label pinned to a point in the scene, a bit like a pin dropped on a map.
It holds text, an image, a video, or a data value, and it stays attached to that exact spot.

Markers exist because a scan does not explain itself.
It shows what a space looks like.
It does not say what the viewer is looking at, why it matters, or what to do next.
A marker carries that missing information and puts it where the viewer is already looking.

Add markers once the models are positioned.
A marker remembers the spot it was pinned to.
Move the model afterwards and the marker stays behind, waiting to be repositioned by hand.


## Marker types

Four types are available from the Add POI section at the top of the panel.
POI is short for point of interest, the term the interface uses for a marker.

| Type | Carries | Use it for |
| --- | --- | --- |
| Text Marker | Descriptions, prompts, annotations | Naming assets, explaining locations, highlighting information in context |
| Image Marker | Photos, equipment images, visual references | Evidence a location or object needs that the 3D model does not show |
| Video Marker | Demonstrations, instructions, scene records | Explaining how an asset works, or showing a process or time-based context |
| Data Marker | Values associated with an object or location | Connecting the visual scene to business or operational information |

## Field reference

Once a marker is placed, its properties appear under Basic Info.

| Field | Description | Recommended usage |
| --- | --- | --- |
| Name | The text on the marker, and how it is listed in the panel on the left. | Name each one after what it describes, so the list stays readable as markers pile up. |
| Style | Whether the marker shows as a text label or a small icon, plus its colour. | Use text when the label needs to be readable at a glance. Use an icon when there are so many markers that text would clutter the view. |
| Scale | The marker's display size in the scene. | Increase for map-level scenes where markers are viewed from a distance. |
| Position | Where the marker sits in the scene. | Set when you place it. Type exact numbers when it needs to land on a specific detail. |
| Height | How far the marker floats above the point it is pinned to, with a **Link line** checkbox next to it. | Lift the marker clear of the surface so the label does not sit on top of the object. Tick Link line to draw a line back down to the exact spot. |
| Visible Distance | Two distances: how close the camera must be for the marker to **Show**, and how far before it will **Hide**. | Set both in busy scenes so markers appear as someone gets close and disappear again when they move away. |

Colour is set with the picker on the Style row.
Position is typed as three numbers: X and Y for the flat position, Z for height.

## Add text marker

For descriptions, prompts, or business annotations.
Text markers suit naming assets, explaining locations, and highlighting information in the 3D context.
Viewers understand a scene element without leaving the spatial view.

## Add image marker

For photos, equipment images, or visual references.

Reconstruction captures geometry, not documentation. Image markers cover what the model cannot:

- A close-up of a serial plate
- A photograph of a defect
- A reference image of how something should look

<VideoDemo src="/demos/project-center/web-videos/editor-editor-panels-marker-panel-add-marker-2.mp4" poster="/demos/project-center/3.3.1标记面板-添加图片标记.poster.jpg" />

## Add video marker

For demonstrations, instructions, or scene records.

Video communicates procedure and sequence that a static annotation cannot.
It suits explaining how an asset operates, showing a process end to end, or recording the state of something at a point in time.

## Add data marker

For values associated with a spatial object or location.

Data markers connect the visual scene to business or operational information.
A model of a piece of equipment presents its geometry.
The same model with operating values attached also presents its current state.
