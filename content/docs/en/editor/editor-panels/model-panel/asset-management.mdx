Asset Management is where 3D model resources enter a project. Upload and load models, remove assets that are no longer needed, and use batch operations when a scene contains many related models.

This is the foundation layer. Markers attach to models, UI interactions target models, and both break if assets are reorganised later, so it is worth settling the asset structure before moving on.

## Panel reference

| Control | What it does | Use it when |
| --- | --- | --- |
| Upload | Adds model files to the project | Bringing reconstructed assets, object models, or supporting resources in |
| Multi-select | Switches the asset grid into selection mode for batch actions | Adding or removing several assets at once |
| List view toggle | Switches between grid and list presentation of the asset panel | The project holds enough assets that names matter more than thumbnails |

Assets appear in the panel as tiles showing the file name and type. Reconstructed scene and object assets use the `.sog` format; supporting files such as cover images appear alongside them.

## Upload and load models

Upload through the Asset Management panel, or drag and drop supported model formats into the panel to add and load assets.

Once a model is loaded it appears in the Model Layer of the Outline on the left, and becomes selectable for placement. Continue with position, rotation, scale, and visibility in [Model Settings](/en/docs/editor/editor-panels/model-panel/model-settings).

## Delete assets

Delete a specific asset to remove unused resources and keep the project structure clean. This is most useful during iteration, when test assets or obsolete models have been superseded by final versions.

Check whether markers or UI interactions reference an asset before deleting it. Markers attach to positions on a model, and UI components can target a model for visibility control, so removing an asset can leave both pointing at something that no longer exists.

## Batch asset operations

Use **Multi-select** to add multiple assets to the scene or delete multiple assets in one action.

Batch handling cuts repetitive work in scenes with many related models, which matters most for complex facilities, map-level assets, and object collections where a scene may hold dozens of individual pieces.

## Why asset structure matters

Every layer above this one references what is placed here. A project with a clear asset structure can be duplicated and adapted; a project where nobody is sure which model is which gets rebuilt.

The practical habit is to load assets in the order they will be discussed, name them meaningfully where the format allows, and settle placement before attaching anything to them.
