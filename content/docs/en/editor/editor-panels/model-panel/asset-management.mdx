Settle the asset structure before adding markers or interface layers.
Everything above depends on it.

Markers are labels pinned to models, and buttons often point at models too.
Rearrange the models later and both stop working, usually with no warning.

Asset Management is where 3D model resources enter a project.


## Panel reference

| Control | What it does | Use it when |
| --- | --- | --- |
| Upload | Adds model files to the project | Bringing reconstructed assets, object models, or supporting resources in |
| Multi-select | Switches the asset grid into selection mode for batch actions | Adding or removing several assets at once |
| List view toggle | Switches between grid and list presentation of the asset panel | The project holds enough assets that names matter more than thumbnails |

Assets appear as tiles showing the file name and type:

- Scanned scenes and objects arrive as `.sog` files, the format VIZZIO reconstruction produces
- Supporting files such as cover images sit alongside them

## Upload and load models

Upload through the panel, or drag and drop supported model formats into it.

Once loaded, the model appears in the list on the left under Model Layer, and you can click it to select and position it.
Continue with position, rotation, scale, and visibility in [Model Settings](/en/docs/editor/editor-panels/model-panel/model-settings).

## Delete assets

Delete a specific asset to remove unused resources and keep the project structure clean.
Most useful during iteration, when test assets or obsolete models have been superseded.

Check first whether anything is pointing at it:

- **Markers** are pinned to spots on the model
- **Buttons** may be set up to show or hide that model

Delete the model and both are left pointing at something that no longer exists.

## Batch asset operations

Use **Multi-select** to add or delete multiple assets in one action.

This matters most for complex facilities, map-level assets, and object collections, where a scene may hold dozens of individual pieces.

## Why asset structure matters

A project with a clear asset structure can be duplicated and adapted. A project where nobody is certain which model is which gets rebuilt.

Three habits keep it clear:

- Load assets in the order they will be discussed
- Name them meaningfully where the format allows
- Settle placement before attaching anything to them
