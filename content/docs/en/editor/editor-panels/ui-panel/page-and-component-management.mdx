Split presentation steps across separate pages rather than stacking components on one.
That is what makes multi-step demonstrations possible.

Put everything on one page and the interface becomes too crowded to read.
A page is a screen. Components are the buttons, text, images, and audio you put on it.


## Component reference

| Component | Description | Recommended usage |
| --- | --- | --- |
| UI Page | An independent interface container for arranging components. | Use separate pages for different presentation steps, content states, or scenario panels. |
| Web Page Component | Embeds URL-based web content with layout and transparency settings. | External dashboards, business pages, or supporting information panels. |
| Text Button | A button with configurable button text, font size, colour, opacity, and alignment. | Clear interaction commands such as navigation, panel switching, or scenario control. |
| Image Button | A button with a custom image background, plus label text and colour. | When an icon or product photo says more than a word would. |
| Text Component | Static text for titles, descriptions, or business copy. | Keep concise and aligned with the current scene or UI state. |
| Image Component | Static image content for visual references or supporting graphics. | Diagrams, reference images, icons, product visuals. |
| Audio Component | Audio content with autoplay and loop options. | Narration, guided demonstrations, contextual prompts. |
| Alignment | Where a component sits, and how it moves when the screen size changes. | Use the same rules across pages so layouts hold up on a phone, a laptop, and a large display. |

Components share a set of common settings:

- **Button text**, the words on the button
- **Font size**, in pixels
- **Color**, entered as a hex code such as `#e2e8f0`
- **Image picker**, for choosing the picture on image-based components
- **X** and **Y**, the position on screen in pixels

## Create UI page

Set the page name and visibility to establish an independent container for component layout.

Visibility lets you prepare interface content in advance and show it only when the workflow calls for it.
That is how a page becomes something a marker or button can reveal on demand.

## Add web page component

Supports URL configuration, transparent background, and layout alignment.

This is the component that connects a digital twin to systems it does not own.
A live dashboard, a maintenance record, or a booking interface can sit inside the scene rather than beside it.

## Component alignment

Alignment controls canvas placement and responsive scaling, keeping layouts consistent across display sizes.

Apply the same rules across pages.
Published projects get opened on whatever the viewer happens to have.
Inconsistent alignment is the normal case, not the exception, and it makes a project appear unfinished.
