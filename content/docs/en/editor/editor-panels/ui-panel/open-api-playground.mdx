**Open API** sits in the UI Panel, between Canvas Settings and Page Management.
Select **Open API Playground** to open it.

<ShotGrid images={['/demos/project-center/screens/open-api-playground.png']} />

The playground is a debugging view for the embedded APIs. You pick a method,
run it against the scene you have open, and see both the result and the code
that produced it.

The UI Panel notes that changes are session-only and reset on refresh. Nothing
you do here is saved to the project, which is what makes it safe to experiment
in.

## The method list

The left column lists every available method, with a search box above it.

| Group | Methods |
| --- | --- |
| Session | `handshake`, `scene.getInfo` |
| Camera | `camera.getState`, `camera.getControllerMode`, `camera.setControllerMode`, `camera.reset`, `camera.flyTo` |
| Models | `model.list`, `model.getVisibility`, `model.show`, `model.hide`, `model.setVisibility` |
| Markers | `poi.list`, `poi.setVisible`, `poi.flyTo` |
| Interface | `ui.list`, `ui.show`, `ui.hide` |

Markers are called **POIs** in the API, short for points of interest. It is the
same object the Marker Panel creates.

## Running a call

Select a method. The right column shows **Debug input**, a JSON field for the
parameters, which starts as `{}` for methods that take none.

Edit the parameters, then select **Run**.

## Code snippet

Below the input, the playground writes the equivalent code, with a **Copy**
button:

```js
const client = createTwinScapeClient({
  targetWindow: window.parent,
  targetOrigin: window.location.origin,
});
await client.ready();
await client.call('camera.getState', {});
```

That snippet is what makes the playground worth using before you write
integration code. Get the call working here, copy it, and paste it into your
application already correct.

## Requests and Events

Two tabs at the bottom of the right column, with a **Clear** button.

**Requests** logs each call with a timestamp and the response body. A
`scene.getInfo` call returns something like:

```json
{
  "sceneId": "indoor",
  "ready": true,
  "projectId": "22"
}
```

**Events** logs what the Viewer pushes back, rather than what you asked for.

## Models and POIs

Below the method list, two live lists of what is in the scene, each with a
**Refresh** button.

**MODELS** shows each model with its id, and buttons for **show**, **hide**, and
**Fill**.

**POIS** shows each marker with its id, and buttons for **flyTo**, **hide**, and
**Fill**.

These call the same methods as the list above, with the id filled in for you. It
is the fastest way to confirm which id belongs to which object before writing a
call by hand.

## Connection state

The top of the right column shows the Viewer state, for example
**Scene ready · indoor**, with two controls.

| Control | What it does |
| --- | --- |
| Reload Viewer | Reload the scene, discarding session-only changes |
| Reconnect SDK | Re-establish the connection without reloading the scene |

Use **Reconnect SDK** when calls stop responding but the scene is still fine.
Use **Reload Viewer** to get back to a clean state.
