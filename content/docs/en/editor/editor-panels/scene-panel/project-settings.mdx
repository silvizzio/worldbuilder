Project Settings holds the four values that identify a project:
its **title**, **cover image**, **scene background colour**, and **project type**.

Three of them appear outside the editor.
The title is what search matches against in the project list.
The cover is the thumbnail shown in that list and on any shared link.
The type tells anyone opening the project what kind of scene to expect.
The background colour is the one setting that only affects the 3D view itself.

Set these when you create a project, then check them again before you share it.

## Field reference

| Field | Description | Recommended usage |
| --- | --- | --- |
| Project Title | The project display name. | Use a clear scene, asset, or customer-facing name so teams identify the project quickly. |
| Project Cover | The thumbnail shown in the project list and shared entry points. | Use a representative view showing the main scene or asset. |
| Scene Background | The background colour of the 3D scene. | Choose a colour that improves contrast against the main asset and suits the presentation context. |
| Project Type | The project category: object, space, or map. | Match the type to the primary asset level so editing and review expectations stay consistent. |

## Set project title

Search in the [Project List](/en/docs/project-center/project-list) matches against the title, so naming decides whether a project can be found later.

- **Titles that name the site, asset, or customer** return the right project on the first attempt
- **Titles like "Test 2"** do not, and the cost falls to whoever needs it next

Consistent naming across a batch also groups related projects together when the list is sorted.

## Set environment background colour

Background colour governs contrast against the asset.
Contrast determines whether a viewer can make out form and detail.
A dark asset against a dark background loses its silhouette regardless of how good the reconstruction is.

Different asset levels need different treatment:

- **Object-level**: a neutral backdrop that isolates the subject
- **Map-level**: a background that does not compete with the terrain

## Set project cover image

Use **Project Cover** to capture and update the thumbnail shown in the project list and shared entry points.

In a portfolio of similar-looking scenes, a representative cover lets a reviewer recognise the right project before opening it.
That is the difference between browsing and opening things one at a time to check.

Capture from a view that communicates what the project contains, rather than whatever the camera happened to be pointing at.

## Set project type

Type should align with the primary content: object-level, space-level, or map-level.

It was set at creation and drove the default camera controller, but it stays meaningful afterwards.
It tells everyone who opens the project what kind of scene to expect and how they will navigate it.

## Why these settings matter

Project identity is what keeps a portfolio usable as it grows.
Accurate titles, recognisable covers, and correct types let teams find, reuse, and duplicate past work instead of rebuilding it.
