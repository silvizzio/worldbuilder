A reconstructed 3D model records a place or object, but viewers also need a way to explore it and understand what they are seeing. WORLD BUILDER provides the tools to arrange those assets, attach information and build an interactive scene that can be shared through a browser link.

A **reconstruction** is a 3D model created by scanning a real place or object, such as a building, site, or product. WORLD BUILDER provides tools to arrange that model, add context, and prepare it for viewers.

Assets from VIZZIO's reconstruction pipeline can be brought into a project, positioned and prepared for viewing in the editor. Viewers with access can open the published link on a laptop or phone without installing the editor.

## The problem this solves

| Without WORLD BUILDER | With WORLD BUILDER |
| --- | --- |
| A 3D file that needs specialist software to open | A URL that opens in any browser |
| A developer to build a viewer around it | A visual editor a non-engineer can operate |
| A release cycle to change anything | Edit, save, preview, reshare in minutes |
| Annotations and context in a separate document | Information attached to the position it describes |
| One asset, one use, rebuilt each time | A project structure that duplicates and adapts |

A project can be duplicated when you need another version, keeping the existing scene as a starting point. This is useful for customer variants, alternate review versions and updated captures of the same site.

## Who this is for

Different team members can take responsibility for the project, 3D assets, annotations and interface. The table below shows where each role works and how reviewers or developers use the finished scene.

| Role | What they do here | Where they work |
| --- | --- | --- |
| Project owner | Owns project identity, type, lifecycle, and access | Project Center, Project Settings |
| 3D content operator | Brings assets in, places them, checks scale and alignment | Model Panel, Debug Tools |
| Solution engineer | Adds business context and builds the interactive layer | Marker Panel, UI Panel |
| Reviewer or customer | Opens a link, explores, gives feedback | Preview and share links |
| Developer | Embeds the published Viewer into an existing product | WebUI Open API |

A solution engineer can add markers, build a guided walkthrough, and publish the scene using the existing reconstruction.

## Where it gets used

The platform stays the same. What changes is the asset level you start from.

- **Map-level**: planning, infrastructure, urban context
  - A reconstructed district or campus becomes a shared reference for planning review and stakeholder presentation
  - Survey data and asset condition sit on the location they describe, not in a report cross-referenced to a map
- **Space-level**: facilities, inspection, walkthroughs
  - A scanned building becomes something a facilities team, tenant, or remote contractor can explore without travelling
  - Video markers show how equipment operates, and image markers carry evidence the model cannot
- **Object-level**: products, equipment, training
  - Fly-to interactions move a viewer through each feature in sequence
  - Visibility toggles reveal internal components
  - Audio narration lets the scene run as a demonstration without anyone presenting it

These scenes give teams a way to share spatial context remotely for inspection, explanation, and review.

## Platform capabilities

The platform supports four parts of the workflow.

- **One pipeline, end to end**
  - VIZZIO handles capture, reconstruction, and asset generation as a single workflow
  - The generated assets feed into the authoring workflow
- **Every asset level in one framework**
  - A campus, a building inside it, and equipment inside that are the same class of object
  - Teams at different scales share one set of conventions instead of three toolchains
- **Authoring in one place**
  - Scene configuration, asset placement, annotation, and interface design in the same editor
  - Keeps scene configuration and supporting information together
- **Publishing inside the workflow**
  - Preview, share, and access control belong to authoring, not a separate deployment
  - A project moves from edit to reviewable link without leaving the platform

## Asset levels

Asset level describes the scale of the 3D content. It is the first decision in any project, and it determines three things in sequence:

- Asset level sets the **project type**
- Project type sets the **default camera controller**
- The controller determines **how a viewer moves through the scene**

| Level | What it covers | Default controller | Typical outcome |
| --- | --- | --- | --- |
| Map | Scanned terrain, city blocks, campuses, outdoor sites | Third person, viewed from outside | Planning review, infrastructure assessment, spatial context |
| Space | Interiors, rooms, buildings, facilities | First person, walking through at eye level | Walkthroughs, remote inspection, tenant and contractor briefing |
| Object | Single objects, equipment, products, vehicles, parts | Third person, viewed from outside | Product demonstration, equipment training, component explanation |

The defaults follow from how someone should move around the scene.
You look at a map or an object from the outside, so the camera orbits around it like turning something over in your hands.
You go inside a room, so the camera walks through it at eye level.
You can change either one later.
