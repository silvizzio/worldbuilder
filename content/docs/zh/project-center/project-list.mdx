搜索与排序可保持项目组合的可查性，前提是项目在创建时已正确命名。

工作区内有五个项目时，两项功能均无必要。达到五十个时则完全依赖两者。而当这一点变得明显时，使搜索生效的命名习惯通常已被省略。

搜索用于直接定位项目。不确定目标时，排序可用于梳理项目范围。

## 操作步骤

1. 使用**搜索**框按关键词查找项目。

2. 或使用**排序**控件按创建时间或最后修改时间排列列表。

3. 打开项目，加载至编辑器。

## 排序方式

| 排序方式 | 排列结果 | 适用情形 |
| --- | --- | --- |
| 最后修改时间 | 最近编辑并保存的项目排在前 | 继续进行中的工作，或查找同事近期改动的内容 |
| 创建时间 | 按创建先后顺序排列 | 追溯项目批次，或按顺序查看早期交付成果 |

日常工作建议按最后修改时间排序，进行中的项目会自动排在前列。核查交付成果、追溯批次，或查找名称已无人记得的历史项目时，按创建时间排序更为适用。

## 影响查找效率的因素

搜索仅匹配项目名称，因此查找效率在更早的环节即已确定——在[项目设置](/zh/docs/editor/editor-panels/scene-panel/project-settings)中，而非此处。

| 做法 | 对列表的影响 |
| --- | --- |
| 使用包含场地、资产或客户信息的描述性标题 | 搜索可一次返回目标项目 |
| 设置有代表性的封面图 | 打开前即可辨识项目 |
| 同批项目采用一致命名 | 排序时相关项目集中显示 |
| 准确设置项目类型 | 列表可反映各项目的场景类别 |

省略这些工作在创建阶段没有成本，但会在三个月后由需要查找该项目、且未参与过该项目的人员承担。

## 意义

随着项目组合增长，搜索与排序可保持项目查找效率。当团队在同一周内于多个项目之间切换——项目创建、编辑器配置、干系人评审与后续维护——这一点尤为重要。

它所避免的是一类具体且成本较高的问题：因无法定位而重建已存在的项目。保持可查的项目组合，是复制与复用具备可行性的前提。
