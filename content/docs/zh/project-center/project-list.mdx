项目列表是工作区内所有数字孪生项目的浏览视图。搜索用于直接定位项目；当你不确定要找什么时，排序可以帮助梳理整个项目组合。

这两项功能的重要性远超初期的直观感受。只有五个项目的工作区不需要它们，有五十个项目的工作区则完全依赖它们。

## 操作步骤

1. 使用**搜索**框按关键词查找项目。

2. 或使用**排序**控件，按创建时间或最后修改时间排列列表。

3. 打开项目，将其加载到编辑器中。

## 如何选择排序方式

| 排序方式 | 排在前面的是 | 适用场景 |
| --- | --- | --- |
| 最后修改时间 | 最近编辑并保存过的项目 | 继续进行中的工作，或查找同事最近改动过的内容 |
| 创建时间 | 按创建先后顺序排列的项目 | 追溯某一批项目，或按顺序回顾早期交付成果 |

日常工作中，按最后修改时间排序是更合适的默认选择，因为进行中的项目无需搜索就会浮到前面。在核查交付成果、追溯批次，或寻找某个已无人记得名称的历史项目时，按创建时间排序更为实用。

## 什么决定了项目能否被找到

搜索只能匹配项目的名称，因此「能否被找到」是在更早的环节决定的——在[项目设置](/zh/docs/editor/editor-panels/scene-panel/project-settings)中，而不是在这里。

| 做法 | 对列表的影响 |
| --- | --- |
| 使用点明场地、资产或客户的描述性标题 | 搜索第一次就能返回正确的项目 |
| 设置有代表性的封面图 | 项目在打开之前就能被辨认出来 |
| 同一批项目采用一致的命名方式 | 排序时相关项目会自然聚集在一起 |
| 准确设置项目类型 | 列表能反映出每个项目承载的场景类别 |

省略这些工作的代价，在创建当下并不会显现，而是在三个月后由一位并未参与该项目、却要找到它的同事来承担。

## 意义

随着项目组合不断增长，搜索与排序能让项目查找保持高效。当团队在同一周内需要在多个项目之间切换——项目创建、编辑器细化、干系人评审与后续维护——这一点尤为重要。

它所避免的是一种具体而昂贵的失败：因为没人找得到，于是重建了一个本就存在的项目。保持可查的项目组合，正是让复制与复用从理论走向实际的前提。
