项目列表用于展示当前工作区内的全部项目。随着项目数量增加，用户需要通过搜索、排序和规范命名快速定位目标项目，避免重复创建或误改项目。

搜索适合在已知项目关键词时直接定位项目；排序适合在不确定项目名称时，通过创建时间或最后修改时间缩小查找范围。

## 操作步骤

1. 在项目列表顶部的搜索框中输入项目名称、客户、场地或其他关键词。
2. 使用排序控件，按创建时间或最后修改时间调整列表顺序。
3. 找到目标项目后，点击项目卡片进入在线编辑器。

## 排序方式

| 排序方式 | 排列结果 | 适用场景 |
| --- | --- | --- |
| 最后修改时间 | 最近保存过的项目排在前面 | 继续当前工作、查找近期协作项目 |
| 创建时间 | 按项目创建先后顺序排列 | 回溯项目批次、查找历史交付版本 |

日常编辑建议优先使用“最后修改时间”排序，正在处理的项目会更容易被找到。进行批次核查或历史版本回溯时，可切换为“创建时间”排序。

## 命名建议

项目列表的搜索结果依赖项目名称，因此项目创建阶段的命名规范会直接影响后续查找效率。

| 建议做法 | 作用 |
| --- | --- |
| 在项目名称中包含客户、场地或资产信息 | 提高搜索命中率 |
| 同一批项目采用统一命名结构 | 便于排序后集中查看 |
| 使用有辨识度的封面图 | 打开项目前即可判断内容 |
| 准确设置项目类型 | 便于区分地图级、空间级和物体级项目 |

建议在项目名称中保留足够的业务信息，例如“客户名称 + 场地名称 + 版本号”。这样即使未参与项目的成员，也能通过关键词快速找到目标内容。

## 使用建议

当工作区内存在多个客户、多个场地或多轮评审版本时，应优先通过搜索和排序确认是否已有可复用项目，再决定是否新建项目。保持项目列表可查，是后续复制、复用和维护的基础。
