项目操作是在项目中心中针对单个项目可执行的生命周期操作，涵盖更新项目、复制项目、以指定访问权限开放评审，以及删除项目。

这些操作与编辑器内部的保存、预览与发布操作不同，后者记录在[发布项目](/zh/docs/editor/project-actions)中。这一区分值得记住：编辑器控制项目「包含什么」，项目中心控制项目「会发生什么」。

## 操作参考

| 操作 | 作用 | 适用时机 |
| --- | --- | --- |
| 编辑项目 | 更新项目名称、封面图与基础信息，或在编辑器中打开该项目 | 项目信息已过时，或需要继续进行场景搭建 |
| 复制项目 | 创建项目副本，复用其场景结构与配置 | 搭建相似场景、准备备选版本，或在重大修改前保留基线 |
| 分享项目 | 生成分享链接或发布入口，并可控制访问权限 | 评审人员或客户需要在不打开编辑器的情况下查看项目 |
| 删除项目 | 从项目组合中移除该项目 | 项目已结束，且正在占用列表空间 |

## 编辑项目

使用**编辑项目**更新项目名称、封面图或基础信息，或重新在编辑器中打开该项目。

准确的项目信息是在列表中快速定位项目的前提，而忽视它的代价，会由下一个需要用到该项目的人承担。请在分享给评审人员之前先行更新，让干系人看到的名称与封面，与他们实际看到的内容相符。

## 复制项目

使用**复制项目**连同场景结构与配置一起复制已有项目。

正是这项能力改变了团队成本的增长方式。一个完成的项目就是一份可用的基线：场景设置已调优、资产已摆放、标记已撰写、界面已搭建。复制它并改造用于新客户、新场地或更新后的采集成果，是从这份基线出发，而不是从空场景开始。

它也是尝试重大改动的稳妥方式。先复制，再修改副本，原项目保持完好，可供对比或回滚。这消除了项目后期面对大幅修改时通常会产生的犹豫。

| 适合使用复制的情形 | 而不是 |
| --- | --- |
| 同一场景面向新客户的变体 | 重新搭建场景并重新添加标记 |
| 同一场地的更新采集成果 | 新建项目并重新配置一切 |
| 可能会撤回的重大结构调整 | 直接就地修改，寄望于撤销功能够用 |
| 供评审对比的备选版本 | 只展示一个版本，另一个靠口头描述 |

## 分享项目

使用**分享项目**生成分享链接。可根据查看者的范围，选择关闭访问、开放公开访问，或设置密码保护。

| 访问设置 | 适用场景 | 需注意 |
| --- | --- | --- |
| 关闭 | 进行中的工作，仅限内部 | 链接依然存在，但接收方打开后无法访问内容 |
| 公开 | 开放性演示、市场推广、广泛传播 | 任何持有链接的人都可以打开该项目 |
| 密码保护 | 客户评审、涉及商业敏感信息的场景 | 密码需通过另一条渠道送达接收方 |

对外分享前请先保存并预览。分享链接呈现的是已保存状态，因此无论你的编辑器屏幕上当前显示什么，评审者打开的都是最后一次保存的内容。

## 删除项目

使用**删除项目**移除不再需要的项目，保持列表聚焦。

删除前请考虑：该项目是否仍可能用于历史查证、客户演示或版本对比。复制的成本很低，而一个已被取代的项目，往往是某个时间点上事物样貌的唯一记录。若有疑虑，给它一个准确的标题和清晰的封面，代价远小于彻底失去它。
