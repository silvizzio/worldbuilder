**项目中心**是登录后首先进入的界面。它包含工作区内的全部项目，并在项目数量增长后保持其可查性。

单个项目不需要管理层，二十个项目则需要。团队的项目累积速度往往超出预期：每个客户一个、每个场地一个、每个采集日期一个，以及效果良好、需要保留的尝试。项目列表足够长之后，查找目标项目将依赖猜测，常见结果是重建了一个已存在的项目。

以下三项能力用于避免该情况，且后一项依赖前一项：

## 项目管理层的作用

单个项目不需要管理层，二十个项目则需要。

交付数字孪生工作的团队，项目累积速度往往超出预期：每个客户一个版本、每个场地一个版本、每个采集日期一个版本，以及效果良好、需要保留的尝试。缺少项目组合视图时，查找目标项目将依赖猜测，常见结果是重建了一个已存在的项目。

项目中心通过三项相互支撑的能力应对这一问题：项目标识用于辨识，搜索与排序用于查找，复制用于复用。

## 与编辑器的关系

项目中心与在线编辑器是同一套工作流的两个部分，分工明确：项目中心管理项目本身，编辑器管理项目内部内容。

| 项目中心 | 在线编辑器 |
| --- | --- |
| 创建、查找、复制、删除 | 场景设置、资产、标记、界面 |
| 项目标识、类型、封面图 | 相机行为、灯光、布局 |
| 访问控制与分享链接 | 保存、预览、发布 |
| 跨项目操作 | 单项目内部操作 |

从项目中心打开项目时，编辑器将加载其已保存状态。离开前请先保存，未保存的编辑内容不会被带入。

## 关于项目复制

复制是此处最少被使用的能力，也是真正影响团队成本增长方式的能力。

结构清晰的项目可复制并改造，用于新客户、新场地或更新后的采集成果，从可用的基线开始，而非从空场景开始。评审周期中的备选版本同理：在重大改动前先复制，修改副本，原项目保持可用，便于对比或回滚。

另一种做法是每次重新搭建，三维项目的成本通常正是在此累积，而这往往并非有意为之。
