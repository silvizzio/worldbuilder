项目中心是 WORLD BUILDER 工作的起点与终点。它负责项目创建、项目组合浏览、搜索、排序，以及推动项目走完生命周期的各项项目级操作。

这里的项目不只是一条文件记录。它包含项目标识、封面图、类型、场景配置、发布状态，以及决定谁可以打开它的访问设置。集中管理这些信息，才能在多个场景同时推进时保持项目组合清晰可查。

## 为什么需要项目组合层

单个项目并不需要管理层，二十个就需要了。

交付数字孪生工作的团队，项目累积的速度往往超出预期：每个客户一个版本、每个场地一个版本、每个采集日期一个版本，再加上那些效果不错、值得保留的尝试。没有项目组合视图，找到正确的那一个就变成了猜测，而最常见的失败是——因为没人找得到，于是重建了一个本就存在的项目。

项目中心通过三项相互叠加的能力来应对这一问题：让项目可辨识的标识、让项目可查找的搜索与排序，以及让项目可复用的复制功能。

## 可以完成的工作

| 能力 | 覆盖范围 | 文档 |
| --- | --- | --- |
| 项目创建 | 从模板或空白项目开始，并初始化默认场景与相机设置 | [创建项目](/zh/docs/project-center/create-project) |
| 搜索与排序 | 通过关键词查找项目，按创建时间或修改时间排序 | [项目列表](/zh/docs/project-center/project-list) |
| 项目级操作 | 编辑、复制、带权限控制的分享，以及删除 | [项目操作](/zh/docs/project-center/project-actions) |

## 与编辑器的关系

项目中心与在线编辑器是同一套工作流的两个部分，分工界限清晰：项目中心把项目作为对象来管理，编辑器则管理项目内部的内容。

| 项目中心 | 在线编辑器 |
| --- | --- |
| 创建、查找、复制、删除 | 场景设置、资产、标记、界面 |
| 项目标识、类型、封面图 | 相机行为、灯光、布局 |
| 访问控制与分享链接 | 保存、预览、发布 |
| 跨多个项目操作 | 在单个项目内部操作 |

从项目中心打开项目时，编辑器会加载其已保存状态。离开前请先保存，未保存的编辑内容不会被带入。

## 关于复制的一点说明

复制是这里最被低估的能力，也是真正改变团队成本增长方式的一项能力。

结构清晰的项目可以被复制并改造，用于新客户、新场地或更新后的采集成果，从一个可用的基线出发，而不是从空场景开始。这同样适用于评审周期中的备选版本：在重大改动前先复制，修改副本，原项目则始终可供对比或回滚。

而另一种做法——每次都重新搭建——正是三维项目成本悄然累积的地方，尽管从没有人真正决定要这样做。
