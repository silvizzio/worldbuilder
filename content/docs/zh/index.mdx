大多数委托进行建筑、场地或产品三维扫描的组织，最终拿到的是一个技术团队之外无人能用的文件。重建成果精确且成本高昂，却停留在一种需要专业软件才能打开、需要专业技能才能修改、还需要开发人员才能呈现给客户的格式中。价值被锁在资产里。

WORLD BUILDER 正是解锁这份价值的一层。它基于 VIZZIO 的三维重建流程，把地图级、空间级与物体级资产转化为可交互的应用，通过一个链接即可在任意设备的浏览器中打开。无需引擎授权，无需构建步骤，无需发版流程。

## 它解决的问题

从一份三维重建资产到业务可用的成果，中间的落差通常以周为单位，并需要专业人力投入。

| 没有 WORLD BUILDER | 使用 WORLD BUILDER |
| --- | --- |
| 需要专业软件才能打开的三维文件 | 任意浏览器都能打开的链接 |
| 需要开发人员围绕它搭建查看器 | 非工程人员即可操作的可视化编辑器 |
| 任何改动都需要走发版流程 | 编辑、保存、预览、重新分享，几分钟内完成 |
| 注释与语境存放在另一份文档中 | 信息直接附着在其所描述的位置上 |
| 一份资产一个用途，每次都要重建 | 可复制、可调整的项目结构 |

真正的转变，是把三维扫描从「一次性交付物」变为「可复用的基础」。项目建立之后，备选版本、面向特定客户的变体以及更新后的采集成果，都可以从复制开始，而不必重新搭建。

## 适用人群

WORLD BUILDER 面向的是团队而非单个操作者，平台结构也体现了这一点。各角色在不同区域工作，并顺畅地交接给下一环节。

| 角色 | 在平台中的职责 | 主要工作区 |
| --- | --- | --- |
| 项目负责人 | 负责项目标识、类型、生命周期与访问权限 | 项目中心、项目设置 |
| 三维内容运营 | 导入资产、完成摆放、检查比例与对齐 | 模型面板、调试工具 |
| 解决方案工程师 | 附加业务语境并构建交互层 | 标记面板、界面面板 |
| 评审人员或客户 | 打开链接、浏览场景、给出反馈 | 预览与分享链接 |
| 开发人员 | 将已发布的 Viewer 嵌入既有产品 | WebUI Open API |

由此带来的实际效果是：理解业务问题的人，不必同时是会操作三维软件的人。解决方案工程师可以添加标记、构建引导式漫游并完成发布，全程无需触碰重建成果本身。

## 应用场景

同一个平台，从不同资产层级出发，服务的业务成果差异显著。

**地图级：规划、基础设施与城市语境。** 三维重建的片区或园区成为规划评审、基础设施评估与干系人汇报的共享参照。标记把测绘数据、规划约束或资产状况直接挂载在其所描述的确切位置上，而不是留在一份还需与地图交叉比对的报告里。

**空间级：设施、巡检与漫游。** 扫描后的建筑成为可漫游的场景，设施团队、潜在租户或远程承包商无需到场即可查看。视频标记讲解设备的运行方式，图片标记补充模型本身无法体现的巡检佐证，界面页面则引导观看者沿既定路线逐步查看。

**物体级：产品、设备与培训。** 扫描后的物体成为可交互的产品体验。飞行交互按既定顺序把观看者引导至每个特性，模型显隐控制可展示内部构件，音频旁白则让场景成为无需销售人员在场也能自助进行的演示。

三类场景的共同成果是一致的：更少的现场走访、更少的预约演示，以及在采集空间的人与需要据此行动的人之间更少的信息流失。

## 平台的整体性来自哪里

四项能力承担了主要作用，每一项都针对三维资产在实际使用中的一种典型失效方式。

**端到端的统一重建流程。** VIZZIO 将采集、重建与数字资产生成作为同一套工作流处理。资产进入 WORLD BUILDER 时已处于可用状态，无需再经历通常比采集本身更耗时的转换与清理环节。

**多层级资产统一框架。** 地图级、空间级与物体级资产在同一结构下组织。对平台而言，一个园区、园区中的一栋建筑，以及建筑中的一台设备，属于同一类对象，因此在不同尺度上工作的团队共享同一套约定，而不必维护三条工具链。

**不被割裂的可视化创作。** 场景配置、资产摆放、标注与界面设计都在同一个编辑器中完成。而多数团队目前的做法是：用三维工具做摆放，用文档写注释，再由开发人员做前端，任何一次改动都要在三者之间往返一轮。

**发布是一等步骤，而非导出动作。** 预览、分享与访问控制是创作流程的组成部分，而不是独立的部署环节。项目无需离开平台即可从编辑状态转为可评审的链接，这正是让评审周期内的迭代真正可行、而非停留在理论上的关键。

## 平台结构

WORLD BUILDER 包含两个工作区，本文档中的绝大部分内容都归属于其中之一。

| 工作区 | 负责范围 | 文档 |
| --- | --- | --- |
| 项目中心 | 项目组合层。创建、查找、复制、分享项目并控制访问权限。 | [项目中心](/zh/docs/project-center/) |
| 在线编辑器 | 内容创作层。通过四个功能面板配置项目的场景、模型、标记与界面。 | [在线编辑器](/zh/docs/editor/) |

此外还有 WebUI Open API，它独立于上述两个工作区，向外部应用开放场景、相机、模型、标记与界面的控制能力，面向需要把已发布 Viewer 嵌入自有产品的团队。

### 在线编辑器

编辑器是项目转化为场景的地方。它将三维视口、四个功能面板与发布控制集中在同一个网页端工作区中。面板的划分是有意为之：场景配置、模型管理、标记交互与界面设计各自负责体验中的一个层次，这正是复杂项目在不断扩展时仍能保持清晰的原因。

<ShotGrid images={['/demos/project-center/0.2在线编辑器.jpg']} />

[查看编辑器文档](/zh/docs/editor/)

### 项目中心

项目中心把项目作为对象来管理，而非管理其内部内容。每个项目都拥有各自的项目标识、类型、封面图、场景配置与发布状态，因此在多个场景同时推进时，不断增长的项目组合依然清晰可查。

## 资产层级

资产层级描述三维内容的规模。它是任何项目的第一个决策点，因为它决定项目类型，项目类型决定默认相机控制器，而控制器又决定观看者在场景中的移动方式。

| 层级 | 覆盖范围 | 默认控制器 | 典型成果 |
| --- | --- | --- | --- |
| 地图级 | 三维重建的地理环境、城市街区、园区、室外场地 | 第三人称 | 规划评审、基础设施评估、空间语境呈现 |
| 空间级 | 室内、房间、建筑、设施 | 第一人称 | 漫游体验、远程巡检、租户与承包商沟通 |
| 物体级 | 单个物体、设备、产品、车辆、零部件 | 第三人称 | 产品演示、设备培训、构件讲解 |

默认值背后的逻辑在于观看者应如何移动。地图与物体场景从外部观察，因此默认采用环绕式控制器；空间场景需要进入并穿行，因此默认采用第一人称。两者都可以更改，但从正确的默认值出发意味着后续调整更少。
