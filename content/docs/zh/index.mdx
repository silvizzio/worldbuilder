首先需要明确起点。**重建成果**指对建筑、场地或产品等真实对象进行扫描后生成的三维模型。

其精度可达厘米级，但单独使用较为困难：查看需要专业软件，修改需要专业技能，向客户展示还需要开发人员参与。

WORLD BUILDER 移除了这些前提条件。它基于 VIZZIO 的三维重建流程，将地图级、空间级与物体级资产转化为可在任意浏览器中通过链接打开的交互式应用。无需引擎授权、构建步骤或发版流程。

## 解决的问题

从完成重建到形成业务可用的成果，通常需要数周时间与专业人力投入。

| 传统方式 | 使用 WORLD BUILDER |
| --- | --- |
| 三维文件需专用软件打开 | 通过链接在浏览器中打开 |
| 需开发人员搭建查看器 | 非工程人员可操作的可视化编辑器 |
| 修改需经过发版流程 | 编辑、保存、预览、重新分享 |
| 注释与说明存放在独立文档中 | 信息附着在其所描述的位置上 |
| 每个用途单独重建 | 项目结构可复制并改造 |

关键变化在于扫描成果的定位：它不再是一次性交付物，而是可持续使用的基础。项目建立后，备选版本、面向不同客户的变体以及更新后的采集成果，均可基于已有项目复制生成，无需重新搭建。

## 适用角色

WORLD BUILDER 面向团队协作场景，平台结构按角色划分。各角色在各自的工作区中完成任务，并在下一环节可直接接续的节点交接。

| 角色 | 职责 | 工作区 |
| --- | --- | --- |
| 项目负责人 | 项目标识、类型、生命周期与访问权限 | 项目中心、项目设置 |
| 三维内容运营 | 资产导入、摆放、比例与对齐检查 | 模型面板、调试工具 |
| 解决方案工程师 | 业务语境标注与交互层搭建 | 标记面板、界面面板 |
| 评审人员与客户 | 查看项目并反馈 | 预览与分享链接 |
| 开发人员 | 将已发布 Viewer 集成至既有产品 | WebUI Open API |

由此带来的实际效果是：理解业务问题的人无需同时具备三维软件操作能力。解决方案工程师可以添加标记、搭建引导式漫游并完成发布，全程无需处理重建成果本身。

## 应用场景

平台本身不变，差异在于起始的资产层级，该层级决定了最终的业务成果。

**地图级：规划与基础设施。** 三维重建的片区或园区可作为规划评审、基础设施评估与干系人汇报的共享参照。测绘数据、规划约束与资产状况直接挂载在其所描述的位置上，无需在报告与地图之间交叉比对。

**空间级：设施与巡检。** 扫描后的建筑可形成漫游场景，设施团队、潜在租户或远程承包商无需到场即可查看。视频标记用于说明设备运行方式，图片标记用于补充模型本身无法体现的巡检信息，界面页面用于引导观看者沿既定路线查看。

**物体级：产品与培训。** 扫描后的物体可形成交互式产品展示。飞行交互按顺序引导观看者查看各项特性，显隐控制用于展示内部构件，音频组件可提供讲解旁白，使演示在无人主持的情况下也能进行。

三类场景规模不同，但结果一致：减少现场走访与预约演示，并降低信息在采集环节与使用环节之间的流失。

## 平台能力

以下四项能力构成平台的基础，分别对应三维项目中常见的四类问题。

**统一的端到端流程。** VIZZIO 将采集、重建与数字资产生成纳入同一流程。资产进入 WORLD BUILDER 时即可直接使用，无需额外的格式转换与清理，而这类工作往往比采集本身更耗时。

**多层级资产统一框架。** 地图级、空间级与物体级资产共用同一套结构。对平台而言，园区、园区内的建筑以及建筑内的设备属于同类对象，不同尺度的工作遵循同一套约定，无需维护三条工具链。

**集中的创作环境。** 场景配置、资产摆放、标注与界面设计在同一编辑器中完成。常见的替代做法是：用三维软件摆放、用文档记录注释、由开发人员实现前端，任何改动都需要在三者之间往返。

**发布纳入创作流程。** 预览、分享与访问控制属于创作流程的一部分，而非独立的部署环节。项目无需离开平台即可从编辑状态转为可评审链接，使评审过程中的迭代成为可行做法，而不必将改动集中到后续处理。

## 平台结构

平台包含两个工作区，本文档的绝大部分内容归属于其中之一。

| 工作区 | 职能 | 文档 |
| --- | --- | --- |
| 项目中心 | 项目组合层：创建、查找、复制、分享与访问控制 | [项目中心](/worldbuilder/zh/docs/project-center/) |
| 在线编辑器 | 内容创作层：通过四个功能面板配置场景、模型、标记与界面 | [在线编辑器](/worldbuilder/zh/docs/editor/) |

WebUI Open API 独立于上述两个工作区，向外部应用开放场景、相机、模型、标记与界面的控制能力，用于将已发布 Viewer 集成至自有产品。

### 在线编辑器

项目在此转化为场景。三维视口、四个功能面板与发布控制集中在同一个网页端工作区中。面板划分是有意设计：场景配置、模型管理、标记交互与界面设计各自负责体验中的一个层次，使复杂项目在规模扩大后仍可维护。

## 资产层级

资产层级描述三维内容的规模。它是项目的第一个决策点：资产层级决定项目类型，项目类型决定默认相机控制器，控制器决定观看者在场景中的移动方式。

| 层级 | 内容范围 | 默认控制器 | 典型成果 |
| --- | --- | --- | --- |
| 地图级 | 三维重建的地理环境、城市街区、园区、室外场地 | 第三人称 | 规划评审、基础设施评估、空间语境呈现 |
| 空间级 | 室内、房间、建筑、设施 | 第一人称 | 漫游体验、远程巡检、租户与承包商沟通 |
| 物体级 | 单个物体、设备、产品、车辆、零部件 | 第三人称 | 产品演示、设备培训、构件讲解 |

默认值依据观看者的移动方式确定。地图与物体场景从外部观察，因此默认采用环绕式控制器；空间场景需要进入并穿行，因此默认采用第一人称控制器。两者均可更改，但从合适的默认值开始可减少后续调整。
