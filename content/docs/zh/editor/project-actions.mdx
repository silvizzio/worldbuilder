编辑器内提供以下交付操作：保存、预览、发布与撤销。

请按上述顺序执行。保存用于写入改动，预览用于打开已保存的版本，发布用于开放给他人访问。

顺序之所以重要，是因为分享链接始终呈现已保存的版本，而非编辑器当前显示的内容。先预览再分享，是确认评审者所见内容符合预期的唯一方式。


## 操作参考

| 操作 | 说明 | 推荐用法 |
| --- | --- | --- |
| 保存 | 写入最新的项目编辑内容并同步至云端存储。 | 在场景、模型、标记或界面发生重要改动后、预览之前保存。 |
| 预览 | 打开已保存的项目成果以供检查。 | 作为发布或分享前的检查点。 |
| 发布与分享 | 创建可分享的项目入口并控制访问状态。 | 开放访问前确认项目已具备评审或演示条件。 |
| 撤销修改 | 放弃未保存的本地草稿改动，回到最后一次保存的版本。 | 迭代过程中当前草稿不宜提交时使用。 |

## 保存与预览

使用**保存**写入修改内容并同步至云端存储。保存后，预览页面显示最新内容，可在发布前确认场景呈现、资产摆放、界面布局与交互行为。

当多个元素同时改动时，该步骤尤为重要。单项改动在编辑器中容易判断，但其协同效果只有在预览中才可见；交互行为尤其无法仅凭创作视图充分评估。

## 发布与分享

使用**发布与分享**生成分享链接。可根据受众为客户演示、团队评审还是外部查看，将访问权限设置为关闭、公开或密码保护。

发布将编辑完成的项目转化为可访问的评审入口，使干系人无需进入编辑器即可查看成果。这一步使数字孪生从工作文件转变为交付物。

<VideoDemo src="/demos/project-center/web-videos/editor-project-actions-2.mp4" poster="/demos/project-center/6.2发布分析.poster.jpg" />

## 撤销修改

使用**撤销修改**放弃未保存的本地草稿改动，回到最后一次保存的版本。该操作可降低误操作的影响，并在改动提交前提供可控的恢复方式。

在反复调整布局、模型定位、界面细节或交互配置时最为适用：将当前草稿与最后一个稳定状态对比，是判断继续推进还是重新开始的最快方式。

对于保存后仍可能需要回退的改动，请先复制项目，详见[项目操作](/zh/docs/project-center/project-actions)。
