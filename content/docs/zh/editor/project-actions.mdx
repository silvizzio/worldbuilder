这些是编辑器内部的交付操作：保存当前修改、预览已保存版本、生成分享入口，或放弃尚未保存的草稿改动。

顺序很重要。保存写入状态，预览呈现已写入的内容，发布则将其对外开放。分享链接始终呈现已保存状态，因此先预览再分享，是确认评审者看到的正是你想让他们看到的内容的唯一方式。

## 操作参考

| 操作 | 说明 | 推荐用法 |
| --- | --- | --- |
| 保存 | 写入最新的项目编辑内容并同步至云端存储。 | 在场景、模型、标记或界面发生重要改动后、预览之前保存。 |
| 预览 | 打开已保存的项目成果以供检查。 | 作为发布或分享前的检查点。 |
| 发布与分享 | 创建可分享的项目入口并控制访问状态。 | 开放访问前先确认项目已具备评审或演示条件。 |
| 撤销修改 | 放弃未保存的本地草稿改动，回到最后一次保存的版本。 | 在迭代过程中，当前草稿不宜提交时使用。 |

## 保存与预览

使用**保存**写入修改后的内容并同步至云端存储。保存后，预览页面会显示最新内容，你可以在发布前确认场景呈现、资产摆放、界面布局与交互行为。

当多个元素同时发生改动时，这一步尤为重要。单项改动在编辑器中很容易判断，但它们协同工作的效果只有在预览中才可见；交互行为尤其无法仅凭创作视图充分评估。

## 发布与分享

使用**发布与分享**生成分享链接。可根据受众是客户演示、团队评审还是外部查看，选择关闭访问、开放公开访问或设置密码保护。

发布会把编辑完成的项目转化为可访问的评审入口，让干系人无需进入编辑器即可查看成果。正是这一步，让数字孪生从「工作文件」变成「交付物」。

<VideoDemo src="/demos/project-center/web-videos/editor-project-actions-2.mp4" poster="/demos/project-center/6.2发布分析.poster.jpg" />

## 撤销修改

使用**撤销修改**放弃未保存的本地草稿改动，回到最后一次保存的版本。这可以降低误操作的影响，并在改动被提交前提供一条可控的恢复路径。

该功能在反复调整布局、模型定位、界面细节或交互配置时最为实用：将当前草稿与最后一个稳定状态对比，往往是判断该继续推进还是推倒重来的最快方式。

对于保存之后仍可能需要回退的改动，请先复制项目，详见[项目操作](/zh/docs/project-center/project-actions)。
