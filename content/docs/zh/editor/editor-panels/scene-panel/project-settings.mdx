项目设置决定了项目如何被标识与呈现。标题、封面图、背景色与项目类型均在此配置，并会体现在项目列表、预览页面以及每一个分享入口中。

这些是编辑器中最不起眼、却最具影响力的设置。它们是干系人在看到其他任何内容之前先看到的东西，也决定了三个月后同事能否找到这个项目。

## 字段参考

| 字段 | 说明 | 推荐用法 |
| --- | --- | --- |
| 项目标题 | 项目的显示名称。 | 使用清晰的场景、资产或面向客户的名称，便于团队快速识别项目。 |
| 项目封面 | 显示在项目列表与分享入口中的缩略图。 | 选择有代表性的视角，让人一眼看出主要场景或资产。 |
| 场景背景 | 三维场景的背景颜色。 | 选择能与主体资产形成对比、并契合展示语境的颜色。 |
| 项目类型 | 项目类别：物体、空间或地图。 | 使类型与主要资产层级匹配，保持编辑与评审预期一致。 |

## 设置项目标题

使用**项目标题**字段更新显示名称。

[项目列表](/zh/docs/project-center/project-list)中的搜索以标题为匹配对象，因此命名决定了项目日后能否被找到。点明场地、资产或客户的标题，第一次搜索就能返回正确结果；而「测试 2」或「新建项目」这类标题则不能，其代价将由下一个需要它的人承担。

项目组合越大，这一点越重要。同一批项目采用一致的命名方式，还能让相关项目在排序时自然聚集在一起。

## 设置环境背景色

使用背景色控件调整三维场景背景，使其契合内容与评审语境。

背景色是一项呈现决策，而非装饰性选择。它决定了资产与背景之间的对比度，而对比度决定了观看者能否辨认出形体与细节。深色资产置于深色背景之上，无论重建质量多高，其轮廓都会被吞没。

物体级、空间级与地图级场景在这里通常需要不同的处理方式。物体展示往往受益于能够凸显主体的中性背景；地图场景则通常需要一个不与地形争夺注意力的背景。

## 设置项目封面图

使用**项目封面**截取并更新显示在项目列表与分享入口中的缩略图。

封面是项目一眼可辨的身份标识。在一组外观相似的场景中，有代表性的封面能让评审者在打开之前就认出正确的项目，这正是「浏览」与「逐个打开确认」之间的差别。

请从能够说明项目内容的视角截取封面，而不是随手用相机当前恰好对着的画面。

## 设置项目类型

使用**项目类型**选择器更改项目类别。

类型应与主要内容保持一致：物体级、空间级或地图级。它在创建时已设定，并决定了默认相机控制器，但此后依然具有意义：它向每一个打开该项目的人传达了应预期何种场景，以及将以何种方式导航。

## 这些设置的意义

项目标识是让「项目组合」真正成为组合、而非一堆文件的那一层。准确的标题、可辨识的封面与正确的类型，让团队能够找到、复用并复制既有成果，而不是推倒重建。

每个项目只需投入几分钟，回报则出现在日后——当一位并未参与该项目的同事需要快速定位正确场景的时候。
