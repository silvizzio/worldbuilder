description: 从空白项目到发布数字孪生成果的十个步骤，说明顺序为何重要，以及在团队之外的人查看之前需要确认哪些内容。

每个 WORLD BUILDER 项目都遵循相同的顺序。这一顺序不是约定俗成，而是一条依赖链：每一步都建立在上一步已确定的基础之上。打乱顺序很少会直接卡住工作，但它意味着之后要重做已完成的部分，而项目时间往往正是在这里悄然流失。

## 推荐工作流

| 步骤 | 目标 | 相关文档 |
| --- | --- | --- |
| 1. 创建项目 | 从模板或空白项目开始，系统会自动生成默认场景与相机设置。 | [创建项目](/zh/docs/project-center/create-project) |
| 2. 配置项目设置 | 设置项目标题、封面图、背景色与项目类型。 | [项目设置](/zh/docs/editor/editor-panels/scene-panel/project-settings) |
| 3. 上传或加载模型资产 | 将三维资产导入项目并保持结构清晰。 | [资产管理](/zh/docs/editor/editor-panels/model-panel/asset-management) |
| 4. 调整模型布局 | 设置位置、旋转、缩放与可见性。 | [模型设置](/zh/docs/editor/editor-panels/model-panel/model-settings) |
| 5. 配置相机行为 | 选择控制器类型、初始视角与视场角。 | [相机控制器](/zh/docs/editor/editor-panels/scene-panel/camera-controller) |
| 6. 配置灯光 | 设置渲染模式、环境光、天空光与主光源。 | [灯光](/zh/docs/editor/editor-panels/scene-panel/lighting) |
| 7. 添加场景标记 | 为位置与模型附加文本、图片、视频或数据。 | [添加标记](/zh/docs/editor/editor-panels/marker-panel/add-marker) |
| 8. 添加界面页面与交互 | 创建页面、添加组件并配置交互。 | [页面与组件管理](/zh/docs/editor/editor-panels/ui-panel/page-and-component-management) |
| 9. 保存并预览 | 保存最新编辑内容，并在发布前检查成果。 | [发布项目](/zh/docs/editor/project-actions) |
| 10. 发布与分享 | 按预期的访问设置生成可分享入口。 | [项目操作](/zh/docs/project-center/project-actions) |

## 三个阶段

这十个步骤可以归为三个阶段，把它们当作分次进行的工作、而非一气呵成的流程，会更有帮助。

**奠基阶段，第 1 至 2 步。** 这些决策现在做成本很低，之后再改代价高昂。项目类型决定相机控制器，而控制器会改变后续每一个摆放决策的判断依据。选错并非致命，但意味着你将在错误的导航模型下评估资产布局。

**搭建阶段，第 3 至 8 步。** 工作量的主体，也是依赖链最紧密的部分。先摆放资产，再添加标注，最后包裹上界面层。每一层都附着在上一层已确定的位置之上。

**交付阶段，第 9 至 10 步。** 这是两个独立的决策，却常被合并为一个。保存与预览确认工作是否正确，发布则决定谁能看到、以何种访问权限查看。把两者区分开来，正是避免半成品场景流到客户手中的关键。

## 为什么是这个顺序

**先设置，后资产。** 项目类型决定默认相机控制器，而控制器类型会改变你对模型摆放的判断。在环绕相机下观感良好的布局，在第一人称视角下可能并不理想。在摆放完成后才确定类型，就意味着要重新检查整个场景。

**先资产，后标记。** 标记附着于位置与模型之上。在附加标记后再移动模型，就需要逐个重新调整标记，而系统不会提示某个标记已经失去了依附对象。

**先标记，后界面。** 界面交互以标记、模型与相机视角为目标。这些目标必须先存在，组件才能指向它们，因此先做界面就等于要做两遍。

**把预览当作检查点，而非最后一步。** 预览反映的是已保存状态，因此它是唯一能可靠呈现评审者所见内容的方式。请在任何重要改动之后就预览，而不是只在最后预览：第 5 步发现的问题只需几分钟，同样的问题拖到第 10 步才发现，代价则是一整个评审周期。

## 时间通常损失在哪里

| 表现 | 根本原因 | 规避方式 |
| --- | --- | --- |
| 布局调整后标记位置出现偏差 | 在附加标记之后又移动了模型 | 先确定资产摆放，再添加标记 |
| 场景在编辑器中效果良好，评审者看到的却不理想 | 从未刻意设置过初始相机视角 | 在分享前就配置初始视角，而不是等收到反馈后再改 |
| 界面组件指向了已不存在的页面或模型 | 交互配置完成后又重命名或删除了目标对象 | 把界面作为最后一层，建立在已确定的目标之上 |
| 评审者看到的版本比预期陈旧 | 改动完成后未保存就直接分享 | 生成链接前先保存并预览 |

## 交付检查清单

在向团队之外的人员生成分享链接前，请逐项确认。这只需几分钟，却决定了这次评审收获的是有价值的反馈，还是一份你早已知道尚未完成的问题清单。

| 检查项 | 确认内容 |
| --- | --- |
| 项目标识 | 标题、封面图与项目类型准确描述了该项目 |
| 场景初始视角 | 初始相机视角对准最相关的区域或资产 |
| 灯光呈现 | 资产清晰可辨，没有过曝或干扰性阴影 |
| 资产摆放 | 模型的位置、旋转、缩放与显隐符合预期 |
| 标记内容 | 文本、图片、视频与数据标记传达了正确的信息 |
| 界面体验 | 页面与组件可读，交互状态清晰 |
| 发布状态 | 项目已保存、已预览，并设置为预期的访问级别 |
